# 丟垃圾：房間與輸入修正（2026-11-17）

## 玩家流程

- 房主在結果畫面按「再來一場」，會準備同一房間的下一場並直接開啟選圖。
  保留房號與玩家；對手準備後，房主開始。不再要求另按「返回大廳」。
- 丟垃圾的玩家介面統一使用「房間」。共用模組、CSS 與內部變數的 lobby 名稱保留。
- 移除 30 FPS 選項，固定以 60 FPS 為繪圖目標；物理及蓄力更新頻率不變。
  儲存偏好時移除舊 `motion` 欄位，原有繪圖、HUD 及重播優化保留。

## 放手到共同出手

舊控制器進入 `sending` 時，繪圖模型沒有將這個階段列為持物狀態；收到房間快照進入
`launch` 才恢復，造成手上垃圾先消失再出現。現在兩階段都持物，實際飛行才移除。
原有約 400 ms 的共同出手準備時間保留，讓雙方收到相同事件後再開始飛行。

交易成功回覆可能早於房間訂閱快照。現在成功回覆不會解除出手鎖；必須收到新的
matchId／seq 才解除，避免在舊回合畫面接受第二次蓄力。每次提交有獨立識別，過期回覆
不能覆蓋新回合；拒絕或錯誤會解除鎖並顯示原因，可在仍有效的回合重試。

原本 `lostpointercapture` 一律取消蓄力，可能在有效手勢尚未放開時中止出手。
現在 capture loss 本身不取消；全域 capture 階段接收 pointerup，touchend 作為漏收
pointerup 的備援，兩事件相繼發生也只出手一次。真正的 pointercancel 或 blur 仍取消
並顯示提示。這些是確認存在的程式路徑，不能據此證實玩家過去兩次的實際原因。

## 連線與提示

原本 watch、poll 或 submit 的任何錯誤都會打開房間面板並顯示一般連線失敗。
該面板本身不能證明對局已經失效。現在：

- 暫時離線顯示重新連線，送出／同步失敗留在場地顯示提示，不強制跳出對局。
- 房間確實消失才開啟建立／加入面板，明確提示房間不存在。
- 權限／驗證失敗引導重新登入或加入；房滿、已開始各有提示。
- 主動離開與逾期未恢復分別記為 `left`、`disconnected`，結果畫面分別說明。
  舊版一般離開原因仍可顯示相容提示。

原有 250 ms 檢查、3 秒心跳及觀察到心跳停止後 15 秒的在線寬限不變。切到背景、
鎖屏、網路切換等可中斷連線；超過寬限可能被對手釋出席位並判負。手動離房也會判負。
房間被刪除、驗證／權限錯誤是不同原因。沒有當時錯誤紀錄，不能回推兩次舊事件。
開發者 console 的 `[Trash Toss room]` 會記錄動作與錯誤碼／訊息，方便後續定位。
正式 Firebase 規則、資料庫部署與斷線寬限未修改。

## 地圖距離：保留現有設計

初速為 `(100 + power × 4.8) × properties.speed × 1.64 × scene.launchScale`。
`properties.speed` 包含物品特性與重量比例的平方根；阻力、風、雨、出手高度和碰撞
也會影響落點。相同蓄力數字並不代表不同場景的初速相同。

| 場景 | 世界寬度 | 初速倍率 launchScale | 出手高度 |
| --- | ---: | ---: | ---: |
| 辦公室／公園／街頭 | 960 | 1 | 102 |
| 客廳 | 600 | 0.72 | 76 |
| 工地 | 2400 | 1.72 | 102 |

例如固定同一紙團、8g、45°、蓄力 85、無風雨、QA 自由飛行：客廳初速約 599.85，
地面水平射程約 480；工地初速約 1432.97，射程約 2058。單位是遊戲世界座標，
不是公尺；實際對戰還會換物品／重量、產生天氣及障礙，鏡頭縮放也影響視覺感受。
目前用不同場景倍率配合場地尺寸，是合理的關卡差異；若未來調整，應比較相同條件下
可觸及的目標區域及操作容錯，而非強制各場景相同絕對射程。本次未改物理平衡。

## 驗證與重跑

```bash
node tools/trash-toss-session-check.js
node tools/trash-toss-render-browser-check.js /usr/bin/google-chrome
node tools/trash-toss-room-check.js
node tools/rooms-check.js
node tools/trash-toss-network-performance-check.js
node tools/trash-toss-performance-check.js --online --throttle=1 --output=/tmp/trash-toss-room-fixes.json
```

控制器檢查涵蓋 120 Hz 裝置上的 60 FPS 排程、capture loss、touchend 備援、
重複放手去重、系統取消。真實 Canvas 檢查涵蓋 30 組像素比較、手勢及舊偏好移除。
兩個真實遊戲頁面以本地 RTDB 替身及 200 ms 快照延遲驗證持物連續、成功回覆先到時
持續鎖定、離線恢復、提交失敗可重試、選圖再戰與房間消失提示。
房間測試另驗證完成比賽再戰保留雙方席位、舊場寫入拒絕及逾期離線原因。
測試不連正式 Firebase，也不能替代 iPhone Safari／主畫面 Web App 的真機驗證。
